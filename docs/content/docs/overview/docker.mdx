# Docker Deployment

## Build and run locally

From the repository root, create the environment file before starting Compose:

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
cp .env.example .env
```

Edit `.env` and fill in `MAAS_API_KEY` only. The mobile-cloud Seedance upstream and model are built in:

- Upstream: `https://zhenze-huhehaote.cmecloud.cn/api/v3`
- Model: `doubao-seedance-2.0`

Do not enter a Base URL or model for this built-in channel. Then build and start the default two-service Compose deployment:

```bash
docker compose up -d --build
```

The `app` service serves the Vite static frontend through Nginx on container port `3000` and proxies the same-origin `/sdk-api` path to `canvas-sdk`. The SDK service has no published host port. Compose sets `SEEDANCE_ENABLED=true` on `app`; the built-in channel is added as read-only, and `doubao-seedance-2.0` is supplied as its default only when no usable video model is already selected. The upstream key stays in the SDK service rather than being sent to the browser. Ordinary channels continue to use their browser-stored credentials and direct or general-proxy requests.

| Service | Role | Host exposure |
| --- | --- | --- |
| `app` | Vite static frontend and same-origin `/sdk-api` reverse proxy | `127.0.0.1:3000:3000` |
| `canvas-sdk` | Mobile-cloud Seedance gateway adapter | No published port |

Open `http://localhost:3000`. The default host binding is `127.0.0.1:3000`; if that host port is occupied, change only the host-side port (for example, `127.0.0.1:13000:3000`) and open the matching local URL. The frontend derives its SDK base URL from `location.origin + "/sdk-api"` automatically.

The SDK stores its RSA key material in the named `seedance-data` volume under `/data/seedance-keys`. Keep this volume across restarts and upgrades: do not run `docker compose down -v`, or historical encrypted videos may no longer be decryptable. Temporary video files are removed after the response; canvases, assets, and generation records remain local to the browser and are not cloud-synchronized.

This integration is intended for local, single-user access. Do not expose the SDK through a public port or reverse proxy: the local Host check is the boundary, and there is no multi-user authentication. The `X-Canvas-SDK: 1` header helps protect the route from CSRF simple requests; it is not user authentication or authorization. Each complete generation request, including multipart media, is limited to 100 MiB; oversized requests receive `413` and are not compressed automatically. Provider limits on media size, duration, and resolution still apply.

The `SEEDANCE_ENABLED` runtime flag is required for injection. A pure static deployment or local Vite dev server without that runtime configuration does not inject the built-in channel.

## Documentation image

The documentation in `docs/` is a separate Next.js standalone application with server capabilities.

## Optional analytics

No analytics are enabled by default. A deployment can enable GA4, Baidu Analytics, or both at runtime:

| Variable | Description |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 measurement ID (`G-XXXX`) |
| `ANALYTICS_BAIDU_ID` | Baidu site ID, the hash after `hm.js?` |

```yaml
services:
  app:
    image: ghcr.io/basketikun/infinite-canvas:latest
    ports:
      - "3000:3000"
    environment:
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

SPA route changes automatically report page views to enabled providers. Only configure analytics IDs on sites you control, and do not commit them to the repository.
